# justask

## Agent skills

### Issue tracker

Issues and tickets are GitHub Issues on this repo, driven with `gh`. See `docs/agents/issue-tracker.md`.

### Triage labels

The five canonical roles use their default names: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: `CONTEXT.md` at the root plus `docs/adr/`. See `docs/agents/domain.md`.

## Commands

- `pnpm lint`: Biome lint and format check (`pnpm format` applies fixes)
- `pnpm typecheck`: strict `tsc`
- `pnpm test`: Vitest, once, on half the cores (`vitest.config.ts` says why); `pnpm test test/ask.test.ts` for one file
- `pnpm build`: emit `dist/`
- `scripts/react-peer.sh <react version>`: after `pnpm build`, the packed package on that React in a temporary project, every piece rendered on the server and one call per hook in jsdom, no real provider; CI runs it on 19.0.0 and 19.1, since the tests see only the lockfile's React (#175)
- `pnpm demo`: the local demo in `demo/` (Vite, handler as dev middleware), real Jev calls with the key in `.env`; one discarded warm-up call on start (`demo/server/warm-up.ts`). `DEMO_KILL_SWITCH=on pnpm demo` turns the kill switch on, and its day's spend and the visitor's limits, counted by the socket's address, are in memory (`docs/workers.md`)
- `pnpm demo:worker`: the demo as its Cloudflare Worker in local workerd (`wrangler.jsonc`, `demo/worker/`), frontend built first; from a worktree pass `--env-file <main checkout>/.env`. every push to `main` deploys it through Cloudflare Workers Builds, and `pnpm demo:deploy` deploys it by hand, by the owner only; see `docs/workers.md`
- `node --conditions=source demo/worker/measure.ts <deployed url> [rounds]`: every flow's dev rows, both languages, to the deployed Worker through Access with the service token in `.env`, real Jev calls, never in CI; each request's CPU time is read from `wrangler tail --format json`, started first (`docs/workers.md`, Measuring CPU). From one address, the visitor's limits now stop it at 20 calls a minute, and the budget at $1 a day; no way past them is built yet
- `node --conditions=source scripts/jev-call.ts ["a request"]`: one real Jev call through `ask`, by hand with the key in `.env`, never in CI; prints latency and cost
- `node --conditions=source demo/recordings/record.ts [table|search|form ...]`: the showcase's recorded runs, the eval runners' three discarded warm-up calls, then two real Jev calls per case named (every case when none is) through the demo's handler, by hand with the key in `.env`, never in CI; rewrites `demo/recordings/<table|search|form>-<en|es>.json` only when every call gives its eval row's expected result. Never edit a recording by hand; rerun the script for the cases a change to the gates serves
- `node --conditions=source demo/eval/search.ts run <en|es> <eval|round2|round3|round4|dev> <n>`: the demo's search eval by hand, real Jev calls, never in CI; `compare <en|es> <eval|round2|round3|round4> <first> <second>` lists flips with no call. The eval sets are frozen by checksum and the kill lines by value in `test/demo-eval.test.ts`; see `docs/search-eval.md`
- `node --conditions=source demo/eval/filter.ts run <en|es> <eval|round2|round3|dev|pair> <n>`: the demo's filter eval by hand (`pair`: #75's status-pair probes, no verdict), real Jev calls, never in CI; `compare <en|es> <eval|round2|round3> <first> <second>` lists flips and `gates <dev n>` prints each field's gate by the approved rule, both with no call. The eval sets are frozen by checksum and the kill lines by value in `test/demo-filter-eval.test.ts`; see `docs/filter-eval.md`
- `node --conditions=source demo/eval/card.ts run <en|es> <set> <n>`: the demo's card eval by hand, real Jev calls, never in CI. The sets, and which of them give a verdict, are listed once in `demo/eval/card-sets.ts`, where a new round names its set (its checksum is still frozen by hand in the test); `run <en|es> office <n> <current|backups|short|rest>` runs #77's office probes under one office label. `compare <en|es> <set> <first> <second>` lists flips on a set with a verdict, `gates <dev n>` prints the intent's and each field's gate by the filter's rule, `office <en|es> <n> <label>` prints an office run's office picks, and `gaps <en|es> <n>` a notoffice run's tag gaps, all with no call. The eval sets are frozen by checksum and the kill lines by value in `test/demo-card-eval.test.ts`; see `docs/card-eval.md`
- `node --conditions=source demo/eval/baseline.ts <run log>...`: the provider probes' median over saved run logs of any flow, with no call; the baseline to write into `demo/eval/probe.ts` before a verdict run, which the three eval CLIs refuse while it is null. See `docs/card-eval.md`, Latency
- `remeasure <en|es> <set> <first n> <n>...` on any of the three eval CLIs (`search.ts`, `filter.ts`, `card.ts`): real Jev calls for only the rows verdict run `<first n>` left pending on transport failures, and still failing after the earlier remeasures named, into the last run named, then run `<first n>`'s report with every answer in place; `merge` with the same arguments prints that report with no call. See `docs/card-eval.md`, Latency

The key's `.env` lives in the main checkout; the demo, the evals, `scripts/jev-call.ts` and the Worker's CPU measure (`demo/worker/measure.ts`, for the Access service token) load it from there when a worktree has none (`scripts/load-env.ts`), so never copy it into a worktree. With `TYPESAFE_API_KEY` already in the environment they look up no `.env`; a malformed or unreadable `.env`, or a bare-repository layout with the key missing, stops them with the file and line, never its contents. The loader's tests pass a stand-in name, never the key's.

Tests import the package by its own name (`justask`, `justask/react`, `justask/jev`, `justask/eval`); the `source` export condition points those at `src/`. The only fake is the provider, `test/fake-provider.ts`; the Jev adapter's tests alone use a fake TypeSafe SDK client from the same file, and one of them stubs `fetch` to check the real SDK sends the environment key once. No test calls a real provider. One exception to the one fake is the clock: a test that needs a fixed today stubs `Date` with `vi.setSystemTime`, never the timers, so the provider timeout stays real; only the replay's tests fake the timers too, below. Another is the viewport: jsdom has no `matchMedia`, so the showcase's tests (`test/demo-showcase.test.tsx`) stub it with a width, to reach the phone layout, and the replay's tests (`test/demo-replay.test.tsx`) stub it with a desktop width and the reduced-motion setting, to reach the typed sentence. Another is an unreachable handler: a handler served in process always answers, so a test of a network failure hands the hook or the demo a `fetch` that rejects (`test/use-card.test.tsx`, `test/demo.test.tsx`, `test/demo-filter.test.tsx`). Another is blocked storage: jsdom's storage always works, so the replay's test of a browser that blocks it spies on `Storage.prototype` to throw (`test/demo-replay.test.tsx`). Another is Cloudflare itself: no handler gives error 1102, so the CPU limit's retry test hands the demo a `fetch` that answers Cloudflare's stop first and the handler after (`test/demo-card.test.tsx`). The last is React's `act`: inside it no render waits, so the calendar's focus race test (`test/demo-card.test.tsx`, #153) renders the `DayPicker` alone, turns `IS_REACT_ACT_ENVIRONMENT` off so React schedules a render as a browser does, and presses a key from a `MutationObserver` before that render's effects run. The Worker's Durable Object ledger is no fake either: `test/demo-durable.test.ts` runs the Worker in local workerd through wrangler's `createTestHarness`, with the fake provider behind it (`docs/workers.md`, Testing the Worker side). The eval tests write their run logs to a fresh directory under the OS temp directory and remove it afterwards, and so does the Code tab's test (`test/demo-snippet.test.ts`), which typechecks each snippet there with the repo's `tsc`, the env loader's test (`test/load-env.test.ts`), which builds a real git repo and worktree there with its own `.env` files, never the real one, and the README's Node test (`test/readme-node.test.ts`), which copies the README's `toNode` there, typechecks it with the repo's `tsc` and serves the handler through it over a real `node:http` server. The handler's tests of its default log spy on `console.error` to keep it quiet and read it; nothing else is stubbed there.

React tests (`test/*.test.tsx`) run in jsdom, chosen per file with `// @vitest-environment jsdom`. They render the pieces against the real handler in process: the hook's `fetch` option hands each request to `createSearchHandler`, wired to the fake provider. They query by role and name and run axe with its contrast rule off (`expectNoAxeViolations` in `test/checks.ts`, beside the demo's shared queries), since jsdom paints nothing and the pieces ship unstyled. Debounce waits are real pauses, for the same reason as the timeout: 200 ms in the hook tests, past the gap between two keys under other sessions' load. The Search, card, filter and replay page files pay their cold start in a `beforeAll` with `warmUp` (`test/checks.ts`), and their first scenario leaves its whole-page axe run to a test of its own, since under load either one ran that test past its 5 s (#120). The demo's tests (`test/demo.test.tsx`) render its `App` the same way, against `createDemoHandler` with the fake provider, and so do the card, filter, showcase, calculator, policy and budget notice tests (`test/demo-card.test.tsx`, `test/demo-filter.test.tsx`, `test/demo-showcase.test.tsx`, `test/demo-calculator.test.tsx`, `test/demo-policy.test.tsx`, `test/demo-stopped.test.tsx`), all with `recordings={null}`, so every case opens idle. Only the replay's tests (`test/demo-replay.test.tsx`) open on the recording files themselves, with a provider that fails, to show the replay makes no call; a replay is paced by timers, and on a loaded machine real ones ran past the test's time and let a replay step overtake the person's, so these tests fake `setTimeout`, `clearTimeout` and `Date` and step the clock. Each of their tests starts as a new browser tab, with `sessionStorage` cleared, since a replay plays once per tab (#135). They stub `jest` as Vitest's, since Testing Library and user-event step only Jest's fake timers, and switch back to real timers before axe, which paces its own work with them. The provider there fails or answers at once, so no provider timeout is ever due. A whole-page axe run still ran a test past 5 s under load (#161), so each of these files that renders the demo's `App`, the replay's included, carries `// @module-tag page`, whose 15 s timeout is set once in `vitest.config.ts`; `test/page-tag.test.ts` fails a page file without it.
